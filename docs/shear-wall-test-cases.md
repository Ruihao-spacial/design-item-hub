# Shear Wall Design — method verification cases

Generated by `npm run cases:doc` from `tests/cases/*.json` (sources with the hand-calc arithmetic: `tests/cases/src/`). Engine: calc v23, schema 13.

**What this document verifies — the method, not the design choices.** Each case fixes (pins) its design — nailing, holdowns / straps, posts, anchors — as manual overrides, listed under *Given (pinned)*. The case then checks how the tool calculates: loads, shares, end forces T / C per load case, load combinations, stacking and transfer, deflection and drift, and demand ≤ capacity of the pinned parts. A change to the design selection logic (e.g. drift sizing or minimum posts) does not change these cases. Where a hand-calc step names a size, it explains why the pinned part is adequate.

**Three layers of testing:** (1) this catalog — the method, reviewed by the engineer; (2) the design selection rules R1–R7 below — automated property tests on every model (`tests/shearWallRules.test.mjs`, `tests/shearWallDrift.test.mjs`), any valid design passes; (3) golden output — a change detector (`npm run cases:diff` shows what changed, `npm run cases:accept` records it). The in-app checks G1–G12 are separate: they run on every project and prove each result balances.

**How to review a case:** read the intent and the model, follow the hand calc, then compare the *Expected* column (hand calc) with *Calculated* (the tool now). The same case is in the local project **SW Verification** (`npm run seed:cases`) — open it and use the **Verification** tab, or Walls → Detailed for the calc sheet.

**Sign convention:** N = vertical force at a wall end (k), + = compression, − = uplift. → = shear toward the right end (left end uplift). Load cases 1.0D / 1.0L / 1.0Lr / 1.0E / 1.0W are unfactored.

**Every case also runs** (`npm test`): T1 line checks G1–G12 · T2 these values · T3 C3 = C4 = the tool and C5 superposition = governing · T4 every tab / calc sheet / elevation / PDF renders · T5 golden output (`tests/cases/golden/`, refreshed with `npm run cases:accept` after review).

**Design selection rules R1–R8 (automated tests, not hand-checked).** V05, V06, V07 and V16 moved here as rule models.

- R1 — Auto nailing = the lightest pattern with v ≤ v_cap·C_hb (seismic and wind); raised for drift → heavier than the strength pick.
- R2 — Auto holdown / strap = the lightest in its table (HDUE; MSTC by floor clear span) with cap ≥ T; OVER only when none carries T; raised for drift → larger than the strength pick.
- R3 — Auto post = the first in catalog order with cap ≥ C and at least the anchorage minimum post (HDUE by size; MSTC floor straps (2)2x).
- R4 — Overrides are never changed; a post override below the minimum post is replaced and flagged.
- R5 — Support-post members are designed for max(ASD, Ω₀ ASD) compression, then R3.
- R6 — WSWH anchor = the smallest footing width W, then embedment d_e, with T_allow ≥ T among the SDC-permitted rows.
- R7 — Drift sizing: each failing story gets the step that cuts the governing wall’s δ more (story nailing step, or that wall’s holdown / strap one size up) until it passes or nothing is left; a nailing step keeps one common pattern per story; bypass reports only.
- R8 — Deflection distribution: at every story each wall with a share gives the same SDPWS Eq. 4.3-1 δ*, Σ V = the story shear; a wall the forces from above already displace more than δ* takes no share; a note when δ(0)/δ* > 0.5.
